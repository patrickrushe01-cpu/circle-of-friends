# iOS Info.plist additions

`ios/` doesn't exist yet in this repo — it's generated by running
`flutter create .` in the project root (see README). That command writes
a fresh `ios/Runner/Info.plist` from Flutter's own template, which would
clobber anything written here in advance. Once you've run it, merge the
following keys into `ios/Runner/Info.plist` by hand.

## Permission usage descriptions

Required — the app will crash on first access to each API without its
string present. Copy mirrors `permission_service.dart`'s
`reasonFor()` text.

```xml
<key>NSContactsUsageDescription</key>
<string>To choose your ten and show their names and photos.</string>

<key>NSCalendarsFullAccessUsageDescription</key>
<string>Meetings with your circle count toward staying in touch.</string>
```

Note what's deliberately absent: there is no `NSContactsUsageDescription`
equivalent for call/SMS, because iOS has no such API for third-party apps
to request in the first place — see DESIGN.md §2. Don't add
`CNContactStore` call-log entitlements or similar; they don't exist and
App Review will reject an app that implies otherwise.

## Background execution (hourly recompute)

`device_calendar`'s calendar collector and the scoring recompute run
opportunistically on iOS via `flutter_background_fetch`'s
`BGTaskScheduler` integration (see DESIGN.md §4). That requires:

```xml
<key>UIBackgroundModes</key>
<array>
    <string>fetch</string>
    <string>processing</string>
</array>

<key>BGTaskSchedulerPermittedIdentifiers</key>
<array>
    <string>com.circleoffriends.app.hourlyRecompute</string>
</array>
```

The matching `BGTaskScheduler` registration call belongs in
`AppDelegate.swift` (also generated by `flutter create .`) — not yet
wired up in this scaffold; `RecomputeScheduler` currently only registers
the Android `workmanager` path (see DESIGN.md's Phase 4 note on
background scheduling).

## Gmail sign-in (`google_sign_in`)

Needed once you've registered the OAuth client from DESIGN.md §11. The
package's own setup docs are the source of truth, but in short:

```xml
<key>CFBundleURLTypes</key>
<array>
    <dict>
        <key>CFBundleURLSchemes</key>
        <array>
            <!-- REVERSED_CLIENT_ID from the downloaded GoogleService-Info.plist -->
            <string>com.googleusercontent.apps.YOUR-REVERSED-CLIENT-ID</string>
        </array>
    </dict>
</array>
```

`GoogleService-Info.plist` itself (downloaded from the Google Cloud
Console OAuth client) goes in `ios/Runner/` alongside `Info.plist`, added
to the Xcode project target — not just dropped in the folder.
